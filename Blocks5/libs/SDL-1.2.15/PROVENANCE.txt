SDL 1.2.15
==========

Compiled from source into blocks5.exe. There is no sdl.dll and no
libs/bin/sdl.lib any more: sdl.dll was the last file in the tree that pulled in
MSVCR120.dll, so it was the last reason the installer had to offer a Visual C++
redistributable.

Taken verbatim from the upstream release, tag release-1.2.15:

  https://github.com/libsdl-org/SDL-1.2   tag release-1.2.15
  commit 457d4e55ffe1b6ad4c4fa4559dbda8360bf8253d (2012-01-20)

libsdl.org is not reachable from the environment this was vendored in, so the
release tarball's own checksum could not be confirmed - the git tag above is
what these files were compared against, file by file. The include/ headers that
were already in the tree, vendored earlier from the tarball, are byte-identical
to it, which is the cross-check that the two match.

Every file under src/ and include/ here is byte-identical to that tag, with one
exception, documented in the file itself: src/main/win32/SDL_win32_main.c has an
#undef UNICODE / #undef _UNICODE prologue, because these projects are
CharacterSet=Unicode while that file uses char buffers with TEXT() literals and
GetCommandLine(). SDL shipped it as an ANSI translation unit; without the undef
the command line collapses to one character at run time and -windowed stops
working.

WHAT IS HERE, AND WHAT IS NOT
-----------------------------
src/ holds exactly the 66 C files that SDL's own VisualC/SDL/SDL.vcproj compiles
for Win32, plus SDL_win32_main.c, plus every header in those directories. Nothing
else from the upstream src/ tree is vendored - it is all for other platforms, or
for compilers this build does not use.

Eight upstream files sit in directories that ARE vendored but are deliberately
absent, because SDL's own Win32 project does not compile them either:

  src/audio/SDL_audiodev.c            Unix /dev/dsp enumeration
  src/audio/SDL_mixer_MMX.c           GCC inline assembly
  src/audio/SDL_mixer_m68k.c          Motorola 68000
  src/video/SDL_yuv_mmx.c             GCC inline assembly
  src/thread/generic/SDL_sysmutex.c   superseded by src/thread/win32
  src/thread/generic/SDL_syssem.c     likewise
  src/thread/generic/SDL_systhread.c  likewise
  src/thread/win32/win_ce_semaphore.c Windows CE

SDL_yuv_mmx.c is the one to remember if this tree ever grows a GCC build:
SDL_yuv_sw.c calls into it when __GNUC__ > 2 and SDL_ASSEMBLY_ROUTINES is set,
which is never true for MSVC and always true for GCC on x86.

CONFIGURATION
-------------
include/SDL_config.h is upstream's SDL_config.h.default, which dispatches on the
platform and lands on SDL_config_win32.h - the stock one, unmodified. So the
driver set is exactly what the shipped sdl.dll had:

  video      WINDIB and DDRAW (plus DUMMY), OpenGL through WGL
  joystick   WINMM - not DirectInput
  audio      DSOUND, WAVEOUT, DISK, DUMMY - all unused, the game plays through
             OpenAL and never calls SDL_OpenAudio
  cdrom      WIN32 - unused
  threads, timers, loadso   Win32

WINDIB comes before DDRAW in the bootstrap list in src/video/SDL_video.c, so the
default driver is windib, exactly as before.

BUILDING
--------
One include directory, libs/SDL-1.2.15/include, which the project already had.
The sources use relative includes for everything internal.

Two extra libraries, both from the Windows SDK, both named by SDL's own project:
winmm.lib and dxguid.lib. dxguid.lib supplies the DirectDraw and DirectInput
GUIDs; ddraw.h, dsound.h and dinput.h are only ever included, never linked
against, because src/video/windx5/SDL_dx5video.c reaches DDRAW.DLL and
DINPUT.DLL through LoadLibrary at run time. That is also why the shipped sdl.dll
imported nothing but WINMM, KERNEL32, USER32, GDI32 and ADVAPI32.

DECLSPEC= is in the project defines. begin_code.h guards it with #ifndef and
would otherwise expand it to __declspec(dllexport) for MSVC on Win32, which is
right for a DLL and wrong for the static build this now is.
